Set up the orchestra workflow in the current project. Never overwrite an existing file without asking: show the user what would change and wait for a yes.

1. **Look at the project first:** package manager and scripts (`package.json`, `Makefile`, `pyproject.toml`, `Cargo.toml` and so on), test runner, git branches (`git branch -a`), whether it has a web UI and a dev server, and how it stores data: compose files, ORM or migration tool, the scheme of any connection URL in `.env.example` or config (`postgresql://`, `mysql://`, `mongodb://`, `redis://`, a SQLite file path), or no data at all. Use this to propose values for "Project settings" instead of asking from scratch.
2. **Test data:** propose the matching recipe from the `orchestra:test-databases` skill and the exact Create, Drop, Capture copy and "Tests read" values for this project. If it keeps no data, propose `none`. If it uses PostgreSQL and has no local setup yet, offer the optional Postgres-in-Docker example; only if the user picks it, copy `${CLAUDE_PLUGIN_ROOT}/skills/test-databases/docker-compose.yml` to `docker-compose.test-db.yml`, and `test-db.sh` and `test-db.ps1` from `${CLAUDE_PLUGIN_ROOT}/skills/test-databases/scripts/` to `scripts/test-db/`.
3. **CLAUDE.md:** if the project has none, create it from `${CLAUDE_PLUGIN_ROOT}/templates/CLAUDE.md` with the values from steps 1 and 2. If it exists, add only the "How we work" and "Project settings" sections. Write `none` for what the project does not have (dev server, test data, browser checks, build). Ask the user to confirm what you could not detect (integration and production branch names, browser sign-in for agents, confidential paths).
4. **docs/HANDOFF.md:** create it from `${CLAUDE_PLUGIN_ROOT}/templates/HANDOFF.md` with the project's branch names, and drop the table columns the project does not use (test data, port). If one exists, offer to add the "How we work" and "Workstream session role" sections.
5. **docs/workstreams/:** create it with a `README.md` of one line: "One handoff note per running workstream, template in the orchestra:handoff-note skill. Each note is deleted before its PR merges."
6. **Specs and decisions:** create `docs/superpowers/specs/` and `docs/decisions.md` (one heading, "Decisions", if new) when missing.
7. Do not change the user's own settings. Tell them what is recommended, so they can apply it themselves: `"autoCompactWindow": 600000` in `~/.claude/settings.json`; the desktop app's auto-archive on PR close turned off; the third-party plugins listed in the orchestra README installed.
8. Show the list of files created or changed and stop. Do not commit unless the user asks.
