Set up the orchestra workflow in the current project. Never overwrite an existing file without asking: show the user what would change and wait for a yes.

1. **Look at the project first:** package manager and scripts (`package.json`, `Makefile`, `pyproject.toml`, `Cargo.toml` and so on), test runner, git branches (`git branch -a`), whether it has a web UI and a dev server, and how it stores data: compose files, ORM or migration tool, the scheme of any connection URL in `.env.example` or config (`postgresql://`, `mysql://`, `mongodb://`, `redis://`, a SQLite file path), or no data at all. Use this to propose values for "Project settings" instead of asking from scratch.
2. **Test data:** propose the matching recipe from the `orchestra:test-databases` skill and the exact Create, Drop, Capture copy and "Tests read" values for this project. If it keeps no data, propose `none`. If it uses PostgreSQL and has no local setup yet, offer the optional Postgres-in-Docker example; only if the user picks it, copy `${CLAUDE_PLUGIN_ROOT}/skills/test-databases/docker-compose.yml` to `docker-compose.test-db.yml`, and `test-db.sh` and `test-db.ps1` from `${CLAUDE_PLUGIN_ROOT}/skills/test-databases/scripts/` to `scripts/test-db/`.
3. **CLAUDE.md:** if the project has none, create it from `${CLAUDE_PLUGIN_ROOT}/templates/CLAUDE.md` with the values from steps 1 and 2. If it exists, add only the "How we work", "Project settings" and "Owner authorizations" sections. Write `none` for what the project does not have (dev server, test data, browser checks, build). Ask the user to confirm what you could not detect (integration and production branch names, browser sign-in for agents, confidential paths). Leave the "Code graph" line to step 8.
4. **docs/HANDOFF.md:** create it from `${CLAUDE_PLUGIN_ROOT}/templates/HANDOFF.md` with the project's branch names, and leave out the registry columns the project does not use (test data, port) when `/orchestra:start-workstream` first creates `.orchestra/workstreams.md`. If one exists, offer to add the "How we work" and "Principal role" sections.
5. **docs/workstreams/ and .orchestra/:** add `.orchestra/` and `graphify-out/` to `.gitignore` (the status round writes its live table to the first; the code graph, if any, lives in the second). Create `docs/workstreams/` with a `README.md` of one line: "One handoff note per running workstream, template in the orchestra:handoff-note skill. Each note is deleted before its PR merges."
6. **Specs, decisions and lessons:** create `docs/superpowers/specs/`, `docs/decisions.md` (one heading, "Decisions", if new) and `docs/lessons.md` (from `${CLAUDE_PLUGIN_ROOT}/templates/lessons.md`) when missing.
7. **Owner authorizations:** walk the user through the "Owner authorizations" block in `CLAUDE.md`. Every level starts at `ask`; change one only if the user says so now.
8. **Code graph:** run "Measure and propose", then "First build" on a yes, from "Code graph" in `${CLAUDE_PLUGIN_ROOT}/skills/maestro/checklists.md`. Write the "Code graph" line in `CLAUDE.md` only after the user answers: `graphify` once built, `declined` on a no, `none` otherwise (also below 500 files).
9. **Branch guard:** offer to install `${CLAUDE_PLUGIN_ROOT}/templates/githooks/pre-push`, which refuses direct pushes to the permanent branches. If the project has no `core.hooksPath` and no hook manager (husky, lefthook, pre-commit), copy it to `.githooks/pre-push`, add `.githooks/* text eol=lf` to `.gitattributes` (a hook with Windows line endings fails), and run `git config core.hooksPath .githooks`; otherwise add it to the hooks setup the project already uses. The hook and its config are per clone, so repeat the two `git config` lines on each machine. Then run `git config orchestra.protectedBranches "<integration branch> <production branch>"`. Git runs hooks with its own `sh` on every platform, Windows included. `${CLAUDE_PLUGIN_ROOT}/templates/githooks/selftest.sh` checks it against a throwaway remote. Also recommend branch protection on GitHub for both branches (require a PR): the hook is a local net, and `--no-verify` or another clone skips it.
10. Do not change the user's own settings. Tell them what is recommended, so they can apply it themselves: bypass permissions for this project only (the desktop app's permission-mode picker per session, or `"permissions": { "defaultMode": "bypassPermissions" }` in this project's `.claude/settings.local.json`, not in the global settings), only in a repository they trust and with the branch guard and owner authorizations in place; `"autoCompactWindow": 600000`; the desktop app's auto-archive on PR close turned off; the third-party plugins installed from the orchestra marketplace (`/plugin install <name>@orchestra` for superpowers, ponytail, impeccable, taste-skill, frontend-design, design, security-audit and playwright-cli; skip any already installed from another marketplace); the maestro on Opus at medium effort and principals on Opus at high; orchestra itself installed at user scope, or `.claude/settings.json` committed if it was installed for the project only, so principals' worktrees load it too.
11. Show the list of files created or changed and stop. Do not commit unless the user asks.
