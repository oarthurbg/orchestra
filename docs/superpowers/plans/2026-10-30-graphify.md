# Code graph Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On a large TypeScript or JavaScript project, the maestro proposes a graphify code graph, builds it once with the owner's yes, keeps it current after each merge, and the explorer and planner query it before they grep.

**Architecture:** Prompt and doc text only. The steps for measuring, proposing and the first build live once, in a new "Code graph" section of the maestro's `checklists.md`; `/orchestra:init` and `/orchestra:close-wave` point to it, and the merge checklist gets the update item. The explorer and planner get the same three-line query rule. A dry run on a scratch copy of a TypeScript app checks parts 3 to 6 of the spec.

**Tech Stack:** Markdown prompt files of the orchestra plugin, git, the graphify CLI (`pip install graphifyy`, checked on 0.9.15), `claude plugin validate`, `claude plugin test`.

**Spec:** `docs/superpowers/specs/2026-10-30-graphify-design.md`

## Global Constraints

- Code pass only: orchestra runs `graphify extract . --code-only`, `graphify update .`, `affected`, `explain` and `path`. Never a paid pass, never free-text `graphify query`, and orchestra never installs graphify.
- TypeScript and JavaScript only, from 500 tracked files, counted with `git ls-tree -r --name-only origin/<integration branch> | grep -cE '\.(ts|tsx|js|jsx|mjs|cjs)$'` (`origin/` left out when the project has no remote).
- Project settings line: Code graph, with the values `none` (the default), `graphify` or `declined`.
- Owner authorizations line: Build the code graph (graphify, first build only), starting at `ask`. The update after each merge asks nothing.
- `graphify-out/` is ignored by git and never committed. One graph lives in the main checkout, on the integration branch; agents in worktrees reach it with `--graph`.
- Implementers, reviewers and the other agents do not change.
- English everywhere. No em dashes. No confidential content: no app, client, brand or people names, no Windows paths from other repositories, no credentials. The scratch app's name and code never appear in the repository or in any commit.
- Commit with `git add <path>` only (never `-A` or `.`), check `git diff --cached --stat` first, never `git stash`, never commit on `main`. Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Before each task's edits, with a clean tree: `git fetch origin` and `git rebase origin/main`, because other sessions push to `main`.
